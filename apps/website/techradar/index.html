Tech radar

What the homelab is built with, and why.

Every technology and technique the homelab uses, tries, keeps an eye on or decided against, each with a one-line reason and a link to where the decision is written down. Those reasons used to be spread over docs, specs and issues. Now they are on one page, in the spirit of Zalando's tech radar (minus the JavaScript).

  • Adopt: in use, and I would choose it again.
  • Trial: in use on trial, or with a known limit I am working on.
  • Assess: researched or planned, not in use yet.
  • Hold: decided against, removed or replaced; the reason says why.

110 entries, updated on 25 November 2026. The numbers on the chart match the legend below it.

Techniques

Adopt

  1. Agent-written pull requests: Agents implement through PRs; CI and the specs keep them honest.
  2. Automatic rollback: A merge that degrades an app is reverted, with an outage guard.
  3. CI as the only gate: No human approval: green CI merges, a degraded app is reverted.
  4. Database majors fix forward: A Postgres major is a one-way door: fresh backup, then forward.
  5. Deterministic first: Scripts, checks and thresholds decide; AI writes and summarises.
  6. DORA metrics: Delivery measured from git, GitHub and alerts, live on the dashboard.
  7. GitOps, main is production: Merging deploys and a revert rolls back; Argo CD tracks main.
  8. Images pinned by digest: A tag can move; a digest cannot.
  9. Keyless signing and SLSA provenance: Own images signed by their workflow and checked by Kyverno.
  10. Page only when urgent and actionable: Everything else is on a dashboard, never on the phone.
  11. Rendered manifests in git: Every object Argo CD applies is reviewed as a file in the pull request.
  12. Restore-tested backups: A backup counts once a scheduled restore of it has passed.
  13. Scheduled pentests: A scoped run against our own names and addresses, findings as issues.
  14. SLOs and error budgets: One number per app, 99.5% over 30 days, from public probes.
  15. Spec-driven development: Requirements, design and tasks merged before the code.
  16. Trunk-based with squash merges: One commit per pull request on a linear main.

Trial

  1. Default-deny network policies: Enforced in a few namespaces; app allow-lists still in audit.
  2. GitHub App instead of PATs: Short-lived tokens for the pentest workflows; PATs remain elsewhere.
  3. Pod Security restricted: Kyverno restricted policies in Audit until their reports are clean.

Assess

  1. Canary tokens: Fake credentials that page when touched.
  2. Chaos experiments tied to SLOs: Break things on purpose, within the error budget.
  3. Disaster recovery site: Where to rebuild if the house is gone, and how fast.
  4. Kubernetes OIDC through Keycloak: Personal API credentials instead of a shared kubeconfig.
  5. Weekly SBOM and CVE scan: What runs, scanned weekly, not only at build time.
  6. Wide events: One rich event per request instead of three signals.

Hold

  1. ADR directory: ADRs rot in a one-person repository; decisions live in the docs.

Tools and languages

Adopt

  1. chrome-headless-shell: Screenshot and layout checks without a pixel diff.
  2. cosign: Keyless signatures with the workflow identity.
  3. GitHub Actions: CI and publishing, every action pinned to a SHA.
  4. GitHub artifact attestations: SLSA v1 provenance for the own images, SLSA Build L2.
  5. gitleaks: No secret reaches a commit, public repository or not.
  6. Go: The dashboard and this radar: one static binary, typed, tested.
  7. Hugo: One pinned binary, no theme, no npm tree, strict CSP possible.
  8. kind: A throwaway cluster in CI for a server-side dry run and a real boot.
  9. Kiro: The agents that write most pull requests, held to the specs.
  10. kubeconform and kube-linter: Schema and practice checks on every rendered manifest.
  11. Kustomize and Helm: Helm charts rendered through Kustomize into deploy/.
  12. OpenSSF Scorecard: A weekly score of the repository's supply-chain practice.
  13. OpenTofu: The cloud resources, applied by a workflow through GitHub OIDC.
  14. OWASP ZAP: The DAST scan of the public names.
  15. pre-commit: The same checks locally on commit and push.
  16. Python: CI scripts and checks, with pytest.
  17. Renovate: Every dependency pinned and updated, automerged on green CI.
  18. SOPS with age: Secrets encrypted in git, decrypted by KSOPS in Argo CD.
  19. talhelper: The Talos machine configs rendered from one file.
  20. Task: One Taskfile for render, checks and Talos operations.
  21. Trivy: The image and config gate in CI.

Trial

Nothing here right now.

Assess

  1. Lore: Memory for coding agents; not evaluated yet, the exact project first.

Hold

  1. Ansible: Node playbooks replaced by Talos machine configs.
  2. Astro and Eleventy: An npm dependency tree to patch for a static blog.
  3. Zola: Fine, but a smaller ecosystem and nothing gained over Hugo.

Platform

Adopt

  1. Alertmanager: Pages through ntfy, quiet hours, only urgent alerts.
  2. Argo CD: Root, three layers, one Application per app, tracking main.
  3. Audiobookshelf: Audiobooks and podcasts.
  4. Calibre-Web: The e-book library.
  5. cert-manager: Let's Encrypt over DNS-01, renewed without anyone noticing.
  6. CloudNativePG: Postgres with WAL and base backups to S3 through Barman Cloud.
  7. external-dns: DNS records from the routes, upsert only.
  8. Grafana: The dashboards, behind Keycloak.
  9. Headlamp: A cluster UI behind Keycloak.
  10. healthchecks.io: The dead man's switch: pages when the cluster goes silent.
  11. Home Assistant: Home automation, local first.
  12. Hubble: Network flows from Cilium, behind Keycloak.
  13. Immich: The photo library, signed in through Keycloak.
  14. Jellyfin: The open-source media server next to Plex, off SSO.
  15. Keycloak: One sign-on for every app, access by group, TOTP for admins.
  16. Kyverno: Baseline policies in Deny, in CI and in the cluster.
  17. Mealie: The household's recipes.
  18. Mosquitto: The MQTT broker for the home devices.
  19. ntfy: Push notifications for pages.
  20. Paperless-ngx: Scanned documents, searchable.
  21. Plex: Films and series on the TVs, off SSO so the TV apps sign in.
  22. PostgreSQL: The one database engine, run by CloudNativePG.
  23. Prometheus: Metrics for 30 days, the SLOs as recording rules.
  24. restic: File backups to S3 and the NAS, restore-tested weekly.
  25. Syncthing: Device sync without a cloud in the middle.
  26. tuppr: Talos and Kubernetes upgrades rolled out node by node.
  27. Vector: Pod and Talos logs shipped as structured events.
  28. Zigbee2MQTT: Zigbee devices on MQTT, no vendor hub.

Trial

  1. SigNoz: Logs on ClickHouse, on trial as the one place for signals.
  2. Tetragon: Runtime detection that pages on critical events; nothing is blocked yet.

Assess

  1. CrowdSec: A shared blocklist at the Gateway; not evaluated yet.
  2. Honeycomb and OBI: Traces from eBPF instrumentation, compared with SigNoz.
  3. KEDA: Event-driven scaling, with the HA work.
  4. OpenBao with External Secrets: Cluster-owned secrets issued, not stored.
  5. Shirudo: eBPF shields for unpatched code paths, once arm64 and Talos fit.
  6. Umami: Cookieless statistics, chosen and not deployed yet.

Hold

  1. Dex in Argo CD: Unused: Argo CD signs in with Keycloak directly.
  2. Loki: Indexes labels only; the fallback if the SigNoz trial fails.
  3. Policy Reporter UI: Grafana is the one view for policy reports.
  4. Seafile: Removed: Syncthing and Paperless-ngx cover its uses.
  5. Service mesh: Cilium already gives the policies and the flows, without sidecars.

Infrastructure

Adopt

  1. AWS S3: Off-site backups with locked object versions.
  2. Cilium: kube-proxy replacement, LB-IPAM, L2 announcements and the Gateway.
  3. Cloudflare DNS: Free zones, DNS-01 for certificates, DNS only.
  4. democratic-csi: iSCSI volumes from the NAS on demand, Retain for data.
  5. Gateway API: One shared Gateway for every public name.
  6. Kubernetes: One API for every workload, run on Talos.
  7. Tailscale: kubectl and talosctl only over the tailnet.
  8. Talos Linux: Immutable, API-only nodes with the machine config in git.
  9. TrueNAS SCALE: The NAS: ZFS, iSCSI and NFS, driven by its API.

Trial

  1. Turing Pi 2 with RK1: Four quiet arm64 nodes on one board, which is a single point of failure.

Assess

  1. NVMe per node: Revisit from the eMMC wear trend.
  2. SELinux enforcing on the nodes: Another layer under the pods.

Hold

  1. Cloudflare proxy and Pages: A token with account write access and data pushed out of the house.
  2. GitHub Pages: Cannot set a CSP header for the public site.
  3. ingress-nginx: Retired upstream; the Cilium Gateway replaced it.
  4. kube-vip: Talos holds the API VIP itself.
  5. kubeadm: The old cluster; rebuilt on Talos.
  6. TrueNAS CORE: Replaced by SCALE in November 2026.
