Tech radar

Avec quoi le homelab est construit, et pourquoi.

Chaque technologie et chaque technique que le homelab utilise, essaie, surveille ou a écartée, chacune avec une raison en une ligne et un lien vers l'endroit où la décision est écrite. Ces raisons étaient éparpillées entre docs, specs et issues. Maintenant elles sont sur une seule page, dans l'esprit du tech radar de Zalando (sans le JavaScript).

  • Adopter : utilisé, et je le choisirais à nouveau.
  • Essayer : utilisé à l'essai, ou avec une limite connue sur laquelle je travaille.
  • Évaluer : étudié ou prévu, pas encore utilisé.
  • Suspendre : écarté, retiré ou remplacé ; la raison dit pourquoi.

112 entrées, mises à jour le 25 novembre 2026. Les numéros du graphique correspondent à la légende en dessous ; pointez-en un pour son nom et son anneau, ou suivez-le jusqu'à sa raison.

Techniques

Adopter

  1. Agent-written pull requests : Des agents implémentent par PR ; le CI et les specs les gardent honnêtes.
  2. Automatic rollback : Un merge qui dégrade une app est reverté, avec un garde-fou en cas de panne.
  3. CI as the only gate : Aucune approbation humaine : le CI vert merge, une app dégradée est revertée.
  4. Database majors fix forward : Une version majeure de Postgres est sans retour : sauvegarde fraîche, puis en avant.
  5. Deterministic first : Scripts, contrôles et seuils décident ; l'IA rédige et résume.
  6. DORA metrics : La livraison mesurée depuis git, GitHub et les alertes, en direct sur le dashboard.
  7. GitOps, main is production : Merger déploie et un revert fait le rollback ; Argo CD suit main.
  8. Images pinned by digest : Un tag peut bouger ; un digest, non.
  9. Keyless signing and SLSA provenance : Nos images signées par leur workflow et vérifiées par Kyverno.
  10. Page only when urgent and actionable : Tout le reste est sur un dashboard, jamais sur le téléphone.
  11. Rendered manifests in git : Chaque objet appliqué par Argo CD est relu comme fichier dans la pull request.
  12. Restore-tested backups : Une sauvegarde compte une fois qu'une restauration planifiée a réussi.
  13. Scheduled pentests : Un test cadré contre nos propres noms et adresses, les résultats en issues.
  14. SLOs and error budgets : Un chiffre par app, 99,5 % sur 30 jours, mesuré par des sondes publiques.
  15. Spec-driven development : Exigences, design et tâches mergés avant le code.
  16. Trunk-based with squash merges : Un commit par pull request sur un main linéaire.

Essayer

  1. Default-deny network policies : Appliquées dans quelques namespaces ; les allow-lists des apps encore en audit.
  2. GitHub App instead of PATs : Des tokens de courte durée pour les workflows de pentest ; les PAT restent ailleurs.
  3. Pod Security restricted : Les policies Kyverno restricted en Audit jusqu'à des rapports propres.

Évaluer

  1. Canary tokens : De faux identifiants qui déclenchent une alerte quand on y touche.
  2. Chaos experiments tied to SLOs : Casser des choses exprès, dans les limites de l'error budget.
  3. Disaster recovery site : Où tout reconstruire si la maison n'est plus là, et en combien de temps.
  4. Kubernetes OIDC through Keycloak : Des accès API personnels au lieu d'un kubeconfig partagé.
  5. Weekly SBOM and CVE scan : Ce qui tourne, scanné chaque semaine, pas seulement au build.
  6. Wide events : Un événement riche par requête au lieu de trois signaux.

Suspendre

  1. ADR directory : Les ADR pourrissent dans un dépôt à une personne ; les décisions vivent dans la doc.

Outils et langages

Adopter

  1. chrome-headless-shell : Contrôles de captures d'écran et de mise en page sans diff de pixels.
  2. cosign : Des signatures keyless avec l'identité du workflow.
  3. GitHub Actions : Le CI et la publication, chaque action épinglée à un SHA.
  4. GitHub artifact attestations : Provenance SLSA v1 pour nos images, SLSA Build L2.
  5. gitleaks : Aucun secret n'atteint un commit, dépôt public ou non.
  6. Go : Le dashboard et ce radar : un binaire statique, typé, testé.
  7. Hugo : Un binaire épinglé, pas de thème, pas d'arbre npm, CSP stricte possible.
  8. kind : Un cluster jetable dans le CI pour un dry run côté serveur et un vrai démarrage.
  9. Kiro : Les agents qui écrivent la plupart des pull requests, tenus par les specs.
  10. kubeconform and kube-linter : Contrôles de schéma et de bonnes pratiques sur chaque manifeste rendu.
  11. Kustomize and Helm : Les charts Helm rendus via Kustomize dans deploy/.
  12. OpenSSF Scorecard : Une note hebdomadaire des pratiques supply chain du dépôt.
  13. OpenTofu : Les ressources cloud, appliquées par un workflow via GitHub OIDC.
  14. OWASP ZAP : Le scan DAST des noms publics.
  15. pre-commit : Les mêmes contrôles en local au commit et au push.
  16. Python : Les scripts et contrôles du CI, avec pytest.
  17. Renovate : Chaque dépendance épinglée et mise à jour, automergée sur CI vert.
  18. SOPS with age : Les secrets chiffrés dans git, déchiffrés par KSOPS dans Argo CD.
  19. talhelper : Les configs machine Talos générées depuis un seul fichier.
  20. Task : Un seul Taskfile pour le rendu, les contrôles et les opérations Talos.
  21. Trivy : Le contrôle des images et de la config dans le CI.

Essayer

Rien ici pour l'instant.

Évaluer

  1. Lore : Une mémoire pour agents de code ; pas encore évalué, d'abord le projet exact.

Suspendre

  1. Ansible : Les playbooks des nodes remplacés par les configs machine Talos.
  2. Astro and Eleventy : Un arbre de dépendances npm à maintenir pour un blog statique.
  3. Zola : Bien, mais un écosystème plus petit et rien de gagné par rapport à Hugo.

Plateforme

Adopter

  1. Alertmanager : Les alertes via ntfy, heures calmes, seulement l'urgent.
  2. Argo CD : Une racine, trois couches, une Application par app, qui suit main.
  3. Audiobookshelf : Livres audio et podcasts.
  4. Calibre-Web : La bibliothèque d'e-books.
  5. cert-manager : Let's Encrypt via DNS-01, renouvelé sans que personne ne le remarque.
  6. CloudNativePG : Postgres avec WAL et sauvegardes de base vers S3 via Barman Cloud.
  7. external-dns : Les enregistrements DNS tirés des routes, en upsert seulement.
  8. Grafana : Les dashboards, derrière Keycloak.
  9. Headlamp : Une interface pour le cluster, derrière Keycloak.
  10. healthchecks.io : Le dead man's switch : une alerte quand le cluster se tait.
  11. Home Assistant : La domotique, en local d'abord.
  12. Hubble : Les flux réseau de Cilium, derrière Keycloak.
  13. Immich : La photothèque, connexion via Keycloak.
  14. Jellyfin : Le serveur média open source à côté de Plex, sans SSO.
  15. Keycloak : Une seule connexion pour toutes les apps, accès par groupe, TOTP pour les admins.
  16. Kyverno : Les policies de base en Deny, dans le CI et dans le cluster.
  17. Mealie : Les recettes du ménage.
  18. Mosquitto : Le broker MQTT pour les appareils de la maison.
  19. ntfy : Les notifications push pour les alertes.
  20. Paperless-ngx : Les documents scannés, avec recherche.
  21. Plex : Films et séries sur les TV, sans SSO pour que les apps TV se connectent.
  22. PostgreSQL : Le seul moteur de base de données, exploité par CloudNativePG.
  23. Prometheus : Les métriques sur 30 jours, les SLO en recording rules.
  24. restic : Sauvegardes de fichiers vers S3 et le NAS, restauration testée chaque semaine.
  25. Syncthing : Synchronisation des appareils sans cloud au milieu.
  26. tuppr : Les mises à jour de Talos et Kubernetes déployées node par node.
  27. Vector : Les logs des pods et de Talos envoyés comme événements structurés.
  28. Zigbee2MQTT : Les appareils Zigbee sur MQTT, sans hub de fabricant.

Essayer

  1. Jamulus (nouveau) : Répéter ensemble depuis des lieux différents, non répertorié, sur la connexion de la maison.
  2. SigNoz : Les logs sur ClickHouse, à l'essai comme endroit unique pour les signaux.
  3. Tetragon : Détection à l'exécution qui alerte sur les événements critiques ; rien n'est encore bloqué.

Évaluer

  1. CrowdSec : Une liste de blocage partagée au Gateway ; pas encore évalué.
  2. Honeycomb and OBI : Des traces issues de l'instrumentation eBPF, comparées à SigNoz.
  3. KEDA : Mise à l'échelle par événements, avec le travail sur la haute disponibilité.
  4. OpenBao with External Secrets : Des secrets du cluster émis, pas stockés.
  5. Shirudo : Des boucliers eBPF pour les chemins de code non corrigés, quand arm64 et Talos suivront.
  6. Umami : Des statistiques sans cookie, choisies, pas encore déployées.

Suspendre

  1. Dex in Argo CD : Inutile : Argo CD se connecte directement à Keycloak.
  2. Loki : N'indexe que les labels ; la solution de repli si l'essai SigNoz échoue.
  3. Policy Reporter UI : Grafana est la seule vue pour les rapports de policies.
  4. Seafile : Retiré : Syncthing et Paperless-ngx couvrent ses usages.
  5. Service mesh : Cilium fournit déjà les policies et les flux, sans sidecars.
  6. SonoBus (nouveau) : Pair à pair : chaque musicien envoie à tous les autres ; un serveur central convient mieux au cluster.

Infrastructure

Adopter

  1. AWS S3 : Sauvegardes hors site avec versions d'objets verrouillées.
  2. Cilium : Remplace kube-proxy, LB-IPAM, annonces L2 et le Gateway.
  3. Cloudflare DNS : Zones gratuites, DNS-01 pour les certificats, DNS seulement.
  4. democratic-csi : Des volumes iSCSI du NAS à la demande, Retain pour les données.
  5. Gateway API : Un seul Gateway partagé pour tous les noms publics.
  6. Kubernetes : Une API pour chaque workload, sur Talos.
  7. Tailscale : kubectl et talosctl uniquement via le tailnet.
  8. Talos Linux : Des nodes immuables, pilotés par API, avec la config machine dans git.
  9. TrueNAS SCALE : Le NAS : ZFS, iSCSI et NFS, piloté par son API.

Essayer

  1. Turing Pi 2 with RK1 : Quatre nodes arm64 silencieux sur une carte, qui est un point de défaillance unique.

Évaluer

  1. NVMe per node : À revoir selon l'usure de l'eMMC.
  2. SELinux enforcing on the nodes : Une couche de plus sous les pods.

Suspendre

  1. Cloudflare proxy and Pages : Un token avec droits d'écriture sur le compte et des données qui sortent de la maison.
  2. GitHub Pages : Impossible d'y définir un en-tête CSP pour le site public.
  3. ingress-nginx : Abandonné en amont ; le Gateway Cilium l'a remplacé.
  4. kube-vip : Talos tient lui-même la VIP de l'API.
  5. kubeadm : L'ancien cluster ; reconstruit sur Talos.
  6. TrueNAS CORE : Remplacé par SCALE en novembre 2026.
