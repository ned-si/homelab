# Structure

## Repository map

| Path | Holds |
| --- | --- |
| `clusters/homelab/` | Argo CD objects only: `root.yaml`, the AppProjects, the three layers, one Application file per app (`<layer>/<app>.yaml`) |
| `infrastructure/` | Layer 1: namespaces, Cilium config, Gateway, cert-manager, external-dns, democratic-csi |
| `platform/` | Layer 2: CloudNativePG, Keycloak, monitoring, exporters, tuppr, backup-verify, Tailscale, Headlamp |
| `apps/` | Layer 3: one directory per app (manifests and Helm values) |
| `*/secrets/` | SOPS-encrypted Secrets for that layer, with a `.example` template each |
| `components/` | Kustomize Components shared by apps (`postsync-smoke`, `presync-backup`) |
| `deploy/` | Rendered manifests Argo CD reads. Build output |
| `bootstrap/` | The root Application, Argo CD values, OpenTofu modules (`aws-backup`, `github-oidc`, `tofu-state`), the tailnet policy |
| `talos/` | talhelper config, patches and the sealed cluster secrets |
| `policies/kyverno/` | Kyverno policies and their tests, run in CI |
| `ci/` | Lists CI reads (Helm releases, active CronJobs, expected Ingresses, kind workloads), vendored CRD schemas |
| `scripts/` | Operator scripts; `scripts/ci/` holds the CI entry points |
| `tests/` | pytest and bash tests for the scripts, Prometheus and Alertmanager rule tests |
| `docs/` | One topic per file, runbooks in `docs/runbooks/`, postmortems in `docs/postmortems/` |
| `.github/` | Workflows, Renovate config, CODEOWNERS |
| `.kiro/specs/`, `.kiro/steering/` | Kiro specs (one directory per feature) and this steering |

Layout and reasons: [docs/architecture.md](../../docs/architecture.md).

## Specs

Two kinds, the index and the rules in [.kiro/specs/README.md](../specs/README.md)
(repo-policy `spec-lifecycle` checks them):

- Change specs: one bounded change, `active` with an issue on the board,
  then `done` with its closed date. Named by outcome.
- Area specs, `living`: how an area works today and its history, no open
  tasks: `platform-talos`, `gitops-delivery`, `backups-dr`,
  `observability-alerting`, `access-identity`, `media-home`.

New work starts as an issue (`area/*`, `type/*` labels). A `type/spec` issue
gets a change spec before its first PR; a `type/task` issue is one PR. Tasks
are ticked with their PR numbers. Deferred or blocked work is an issue with
that label, never an unticked task. How specs, steering, skills, hooks and
MCP servers fit together:
[docs/spec-driven-development.md](../../docs/spec-driven-development.md).

## Rendered manifests

- Never edit `deploy/` by hand. Change the source, run `task render`, commit
  both. CI (`task render:check`) fails when `deploy/` differs from its sources.
- One file per object: `deploy/<layer>/<app>/<kind>-<name>.yaml`.
- Not rendered: the `*/secrets/` directories (rendering would decrypt them)
  and upstream Helm charts, which stay versioned `chart:` sources.

## Secrets

- Only in `*.sops.yaml` files, encrypted to the age key in `.sops.yaml`;
  names and namespaces stay readable, values are encrypted.
- Plaintext sources (`secrets.local.env` and any `*.local.*` file) are
  git-ignored working copies on the operator's Mac. Never commit, quote or
  print them.
- PostgreSQL passwords are generated by CloudNativePG and never exist in git.
- Details: [docs/secrets.md](../../docs/secrets.md).

## Naming

- Each app under `apps/`: directory, Application and namespace share one
  name (`immich`, `mealie`, `theater`, ...).
- CNPG clusters: `<service>-postgresql` (`mealie-postgresql`,
  `sonarr-postgresql`, `home-assistant-postgresql`); `immich-db` and
  `keycloak-db` keep their historical names.
- Public hostnames: `<prefix>.lilalala.com`, the prefix chosen per app
  (`media` for Immich, `cook` for Mealie).
- Commits and pull request titles: Conventional Commits, titles under 70
  characters, every commit signed. Branches: `<type>/<topic>`.
- Kiro specs: `.kiro/specs/<name>/` with `requirements.md` (and its header),
  `design.md`, `tasks.md`. Everything else under `.kiro/` is local and git-ignored.
